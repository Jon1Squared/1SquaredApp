## Files and changes

1. **Tenant registry in core (`core/schemas/tenant-registry.schema.json` — new, `core/src/tenancy/tenantRegistry.ts` — new, `R403`, `R413`):**
   - Schema-validated environment tenant registry (ADR 0030 §2, moved into S0-14 so `migrate` and S0-19 share a single source of truth). Each entry holds `tenantId`, `slug`, `environment`, `postgresHost`, `postgresDatabaseName`, `keyVaultUri` (from `tenant.bicep` output so 24-char truncated vault names are never re-derived, `R413`), `packageDir`, `timeZone` (default `'Europe/London'`), and `enabled: boolean`.
   - Model A has a single entry; Model B lists active hosted tenants. Web requests **never** resolve their tenant from the registry (still token-only per Rule 4).
2. **PostgreSQL driver, transaction-scoped `SET LOCAL ROLE`, privilege model & readiness check (`package.json`, `core/src/tenancy/postgresPoolManager.ts`, `core/src/tenancy/tenantScopedRepository.ts`, `R401`, `R402`, `R403`):**
   - Add `pg` (`^8.x`) to `dependencies` and `@types/pg` to `devDependencies`. Add an ESLint `no-restricted-imports` rule in `eslint.config.mjs` (plus a contract test) forbidding `import ... from 'pg'` outside `core/src/tenancy/**` (Owner Decision 2).
   - **Pools & PgBouncer compatibility (`R401`):** `TenantPostgresPoolManager` resolves `(host, port, databaseName, tenantRole)` strictly from `TenantContext` (`assertValidTenantContext(ctx)` + optional `database.dedicatedServerHost` in `tenant-config.schema.json`), caps each pool at `max: 5` connections per tenant per replica by default, evicts idle pools after a configurable timeout, and connects through PgBouncer (`port: 6432` in Azure / CI PgBouncer, `pool_mode = transaction`) using Entra ID tokens for **`runtimeIdentity`** in Azure (`PLATFORM_POSTGRES_AUTH_MODE=entra_managed_identity`, zero passwords) or the non-superuser `runtime_login` locally/in CI.
   - **Every unit of work runs in a transaction with `SET LOCAL ROLE` (`R401`):**
     - There is **no** non-transactional `withTenantConnection` or session-level `SET ROLE` / `RESET ROLE` path (which would leak or drop across PgBouncer transaction-pooled server connections).
     - Both `withTenantReadTransaction(ctx, fn)` (`BEGIN READ ONLY`) and `withTenantTransaction(ctx, fn)` (`BEGIN`) run inside an explicit transaction whose **first statements** after `BEGIN` are `SET LOCAL ROLE <validated_tenant_role>` (`/^[a-z0-9_]{1,63}$/`) and `SET LOCAL statement_timeout = ...`, ending with `COMMIT` (`ROLLBACK` on error). `SET LOCAL ROLE` resets automatically when the transaction ends, making PgBouncer transaction pooling 100% deterministic.
   - **Database privilege model (`R402`):**
     - PostgreSQL checks `CONNECT` on the initial login (`runtime_login`), not after `SET LOCAL ROLE`; **cross-tenant protection comes from `NOINHERIT` + per-tenant schema and object privileges**:
       - `runtime_login` (`id-runtime-<env>`) is created with `LOGIN NOINHERIT NOCREATEDB NOCREATEROLE NOSUPERUSER` and granted role membership `GRANT role_tenant_<slug>_<env> TO <runtime_login>;`, holding **zero** direct schema, table, or sequence privileges.
       - For every tenant database: `REVOKE ALL ON DATABASE pg_tenant_<slug>_<env> FROM PUBLIC;`, `GRANT CONNECT ON DATABASE pg_tenant_<slug>_<env> TO <runtime_login>, role_tenant_<slug>_<env>;`, `REVOKE CREATE, USAGE ON SCHEMA public FROM PUBLIC;`, `GRANT USAGE ON SCHEMA public TO role_tenant_<slug>_<env>;`.
       - Migrations run as `migrate_login` (`id-migrate-<env>`, Entra admin on direct port `5432`) and transfer/grant object privileges exclusively to `role_tenant_<slug>_<env>` (`ALTER DEFAULT PRIVILEGES FOR ROLE <migrate_login> IN SCHEMA public GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO role_tenant_<slug>_<env>;` and `GRANT USAGE, SELECT ON SEQUENCES TO role_tenant_<slug>_<env>;`, except append-only `audit_entries` in S0-15 which gets `SELECT, INSERT` only).
       - Consequently, any query run by `runtime_login` *without* `SET LOCAL ROLE` fails with `permission denied`, and a pool pointed at Tenant B's database attempting `SET LOCAL ROLE role_tenant_a_<env>` fails because `role_tenant_a_<env>` has zero `USAGE` or table privileges in Tenant B's database.
   - **Schema readiness check (`TENANT_SCHEMA_NOT_READY`, ADR 0028 §4, `R403`):**
     - `CORE_REQUIRED_SCHEMA_VERSION` (`'0006'` in S0-14) defines the exact migration version required by the running code revision. On first use of a tenant pool (cached per `(tenantId, revision)` once ready; re-checked on subsequent requests if not yet ready), `TenantScopedRepository` checks `schema_migrations` in that tenant's database and refuses immediately with **`TENANT_SCHEMA_NOT_READY`** if unmigrated or below `CORE_REQUIRED_SCHEMA_VERSION` — ensuring a new revision never serves traffic for a tenant whose migration has not completed.
   - Row-level second check (`assertRowTenant(ctx, row.tenant_id, table)`) and sanitised `pg` error wrapping (never echoing SQL text, parameters, or row contents).
3. **Real SQL `TenantMigrationRunner` & single `run-job migrate` entry point (`core/src/tenancy/migrations/index.ts`, `scripts/run-job.ts` -> `dist/jobs/run-job.mjs`, `R401`, `R403`, `R404`):**
   - Rewrite `TenantMigrationRunner` to connect **directly to port `5432`** (`PLATFORM_POSTGRES_MIGRATE_PORT=5432`, bypassing PgBouncer) as `migrate_login`, running each pending migration (`upSql` or `rollbackVersion` `downSql`) in its own transaction (`BEGIN ... COMMIT`) guarded by `pg_advisory_xact_lock(hashtext('onesquared_migrate:' || tenantId))`, verifying SHA-256 checksums in `schema_migrations`. Never runs on web app startup.
   - Wire `migrate` into the **single** job runner entry point (`npm run job -- migrate` locally / `node dist/jobs/run-job.mjs migrate` in the container, iterating `loadActiveTenantRegistry()`). If one tenant fails migration, its transaction rolls back, its rollout stops (`TENANT_SCHEMA_NOT_READY`), **other tenants continue migrating** (ADR 0028 §4), and the runner exits non-zero after completing the sweep.
   - Add **`0005_key_dates_matter_restrictions_expand`** (`matter_restriction_metadata`, reversible `DROP TABLE`) and **`0006_document_generation_tenant_config_expand`** (`document_generation_tenant_configs`: `tenant_id TEXT PRIMARY KEY`, `config_json JSONB NOT NULL`, `updated_by_id TEXT`, `updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`, reversible `DROP TABLE`).
4. **Delete in-memory simulation, introduce re-entrant `storeLock.ts`, & move Document Generation + Document Store metadata off the JSON store (`Owner Decisions 2 & 6`, `R405`, `R406`, `R418`):**

   - **Delete both JSON dual-write bridges (`R405`):** delete `syncStoreToRepository` (`src/server/documentGenerationServices.ts:263`) / `persistRepositoryToStore` (`:485`, removing repository-mirroring `saveStore` at `:499`) and delete `ensureRepositorySyncedWithStore` (`src/server/documentStoreServices.ts:286`) / `persistRepositoryToStore` (`:326`, removing `saveStore` at `:382`). Both modules now read and write their templates, versions, documents, links, usage events, locations, folder scopes, lifecycle jobs, reconciliation findings, audit events, and config overrides (`0001`, `0002`, `0006`) **solely in PostgreSQL**!
   - **Start re-entrant `src/server/storeLock.ts` in `S0-14` (`R406`, `R418`, retired in `S0-20`):** add `withJsonStoreWriteLock(fn)` backed by a process-wide FIFO async mutex **made re-entrant for the same async call chain via `AsyncLocalStorage`** (`AsyncLocalStorage<{ compensator: RecordDeltaCompensator }>` — nested `withJsonStoreWriteLock` calls reuse the active lock without deadlocking). Until `S0-15` moves `audit_entries` to PostgreSQL and `S0-16` moves directory/matters, `documentGenerationServices.ts` mutations that write to PostgreSQL and then call `appendAudit` (`:904`) + `saveStore(store)` (for `store.audit` only), as well as `executeMerge` (`src/server/services.ts:5639`), run inside `withJsonStoreWriteLock` + `RecordDeltaCompensator`. Their reads of `people`, `organisations`, `links`, and `matters` remain on `getStore()` until `S0-16` (`values`/`teams` until `S0-17b/c`).
   - Convert callers to `await`: `core/src/domain/document-generation/{approvalWorkflow,generationService,packageTransfer,usageService}.ts`, `core/src/domain/documents/{lifecycle,reconciliation}.ts`, `src/server/documentGenerationServices.ts`, `src/app/api/documents/download/route.ts:50, 63`, `src/server/documentStoreServices.ts` + `src/app/api/document-stores/route.ts:63,74,142,169,185,205,224,241`, and `executeMerge` (`src/server/services.ts:5639`, `mergeRecordsAction` at `src/app/actions.ts:407`, plus 27 `executeMerge` test calls in `core/tests/rbac.test.ts`).
5. **One-off Document metadata import & release cut-over runbook (`scripts/import-store-to-postgres.ts` -> `dist/jobs/import-store.mjs`, `docs/runbooks/store-cut-over.md`, `docs/runbooks/tenant-database-restore.md`, `R402`, `R404`, `R405`, `R407`):**
   - Add `scripts/import-store-to-postgres.ts` (bundled by `scripts/build-jobs.mjs` into `dist/jobs/import-store.mjs`, runnable locally as `npm run db:import -- --modules documents,document-store` and in Azure via the `store-import` Container Apps job) importing `store.documentTemplates`, `documentTemplateVersions`, `documents`, `documentLinks`, `templateUsageEvents`, `documentGenerationConfigOverride`, `matterDocumentLocations`, `documentStoreFolderScopes`, `documentLifecycleJobs`, `documentReconciliationFindings`, `documentStoreAuditEvents`, and `documentStoreConfigOverride` idempotently (`ON CONFLICT ...   - Idempotent one-off import test for Document Generation & Document Store metadata (`R405`), plus `src/server/__tests__/storeLock.test.ts` testing FIFO serialisation across concurrent callers and `AsyncLocalStorage` re-entrancy on nested calls without deadlock (`R418`).

## Acceptance criteria

- `TenantScopedRepository` runs every read and write inside a transaction starting with `SET LOCAL ROLE`, routed through PgBouncer (`transaction` mode) as `NOINHERIT` `runtime_login`; zero code outside `core/src/tenancy/` imports `pg`.
- `tenantRegistry.ts` is live in core; `dist/jobs/run-job.mjs migrate` connects directly to port `5432` as `migrate_login`, isolates per-tenant failures, and unmigrated tenants fail closed with `TENANT_SCHEMA_NOT_READY`.
- `PostgresTenantCluster`, repository in-memory `Map`s, and the DocGen/DocStore JSON sync bridges are deleted; Document Generation and Document Store metadata are imported via `dist/jobs/import-store.mjs` and run solely on PostgreSQL.
- CI runs `postgres:16` + `pgbouncer` (`transaction` mode); `tenant-database-restore.md` and `store-cut-over.md` are added; all PgBouncer, `R402` privilege, isolation, and e2e tests pass (`npm run ci`).
