# Roadmap feature status review

Reviewed on 6 November 2026 against branch `fix/testing-fixes` (commit `a0a5534`). This was a read-only review: each item was checked in the domain logic, services, actions, API routes, UI, seed data, schemas, extensions and tests. Statuses use a strict bar. **Completed** means the item works end to end (data model, logic, UI and server-side permissions) and has tests.

## Findings that affect most items

1. **Single-tenant storage.**
   - Everything except documents, the SharePoint document store and document generation lives only in the transitional JSON store (`src/server/store.ts`). That store is approved by ADR 0001, but no feature has moved off it yet.
   - `TenantKeyDateRepository` exists in core but only the isolation tests use it; at runtime, key dates are in `store.keyDates`.
   - PMS financial data comes from one process-wide SQLite file (`src/pms/pmsSource.ts`, `getPmsSource()`) with no tenant scoping (rule 4).
   - The Postgres database-per-tenant layer (`PostgresTenantCluster`) and the per-tenant migration runner are simulated in memory, and `core/infra/main.bicep` defines no Postgres resource.
2. **No server-side permission checks.** Most server actions only check that the user is signed in (`withActorId`). Hiding a screen is not access control. The worst cases:
   - `clearAllDataAction` / `resetDemoDataAction`: any user can wipe or reset the store, and the wipe writes no audit entry.
   - `approveSignOffAction`: any user can approve a partner sign-off.
   - `anonymiseExpiredEnquiriesAction`: any user can bulk-anonymise enquiries.
   - `reassignLeaverOwnedRecordsAction`.
   - `executeMerge`.
   - Every Admin save action: teams, lists, custom fields, org structure, enquiry and task settings, matter costs config, party taxonomy.
   - PMS link and create-from-PMS.
   - `saveTaskRecord` (`canUserReassignTask` is imported but never called).
   - `/api/matters/extract`, which creates people and organisations with no create permission.
3. **Finance data sent to every user.** `getAppSnapshot` returns firm-wide PMS figures to everyone; the finance view is only hidden in the browser. Firm-wide PMS summaries are also not filtered for restricted (staff or ethical-wall) matters.
4. **Demo content presented as real.**
   - `HomeClient.tsx` (138 `hasDemoSeedData` branches) and `MatterProfileClient.tsx` show hard-coded panels, KPIs and statuses, and many buttons only show a toast.
   - Some person and organisation profiles show a fabricated "Sanctions & PEP: Clear" status.
   - `HomeClient.tsx` hard-codes demo matter codes in what should be platform UI.
5. **Secrets (rule 5).**
   - An Ideal Postcodes API key is hard-coded as a fallback in `src/domain/addressLookup.ts:16-18` and exposed through `NEXT_PUBLIC_`.
   - `/api/matters/extract` accepts an Anthropic API key from the browser (`apiKeyOverride`).
6. **Tenant config declared but ignored.** Nothing reads `aiProviderChoice`, `clientCodeAllocation` or `companiesHouseApiKeyVaultRef`.
7. **Isolation tests (rule 9).** Two-tenant tests cover key dates, documents, the SharePoint store, RBAC and conflict/restricted-matter behaviour. They do not cover enquiries, quotes, tasks, matters CRUD, finance, sign-offs or HR.
8. **Help articles (rule 11).** Only 19 articles exist. There are none for quotes, matter costs, matter opening and risk, CDD, engagement letters, tasks, PMS finance, Home pages and KPIs, People/HR, retention, sign-offs or search.
9. **No client-specific code found in `core/`.** The only client code is the `nalf-matter-costs-governance` extension, which correctly uses `@platform/core-api`.
