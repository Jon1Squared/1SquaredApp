# Platform Technical Notes

Technical implementation details referenced by [architecture and Help articles](../../src/docs/registry.ts) belong in `docs/` rather than end-user Help pages (Stage 1 §6 rule 6) or slice work-tracking files.

- **Global search (`global-search`):** Debounced workspace search runs through `searchGlobalRecordsAction` (`src/app/actions.ts`) and `TenantSearchRepository` (`core/src/tenancy/searchRepository.ts`) against migration `0018_tenant_search_indexes_expand` trigram and full-text indexes.
- **PMS finance & import (`finance-data-and-permissions`):** Delivered through `src/server/financeServices.ts` ([ADR 0029](../decisions/0029-finance-data-delivery.md)) and `TenantPmsRepository` (`core/src/tenancy/pmsRepository.ts`, `src/pms/pmsSource.ts`, [ADR 0028](../decisions/0028-tenant-database-and-repositories.md) / `S0-18` / `0013_pms_per_tenant_expand`). Imports run per tenant via `npm run pms:import -- --tenant <slug>` using `loadActiveTenantRegistry()` and `getTenantConfigurationForRegistryEntry`, rejecting ambiguous multi-tenant runs (`PMS_IMPORT_TENANT_REQUIRED`, `R618`), live runs (`PMS_IMPORT_LIVE_FORBIDDEN`), and unknown/disabled tenants (`TENANCY_UNREGISTERED_JOB_TENANT`, `R584`).
- **Matters, enquiries, quotes & restricted visibility (`matters-enquiries-tasks-and-navigation`):** `quote:view` grants quote screen access to `enquiries_coordinator`, `intake`, `legal_secretary`, `fee_earner`, `supervisor`, `risk_compliance`, `partner`, `managing_partner`, and `admin` (not `finance`), enforced via `buildRecordVisibility` and SQL visibility predicates; restricted/walled matters (`isStaffMatter`, `hasEthicalWall`, `restrictedAccessUserIds`, `S0-16`, `R409`, `R417`, `R448`) and personal `Draft` enquiries enforce parity across `TenantMatterRepository`, `runMatterConflictSearchRecord`, `saveMatterRecord`, `updateMatterConflictRecord`, `conflict_search_restricted_match` structured logs, and server `buildServerConflictCheckRecord` (`submit_referred`, `Approved`/`Declined`, `hasUnapprovedRestrictedMatches`, `matter:restricted:access`), while users with `matter:restricted:access` can see register records on restricted matters on Home (`registerRepository.ts:524-537`).
- **Conflict preview rate limiter (`R705`, `R724`):** `previewIntakeDuplicatesAndConflictsRecord` (`src/server/services.ts`) enforces a per-tenant, per-actor sliding-window limit of 30 `includeConflicts: true` checks per minute (`conflictPreviewTimestampsByActor`) in memory on each application instance, pruning expired empty actor buckets automatically.
- **Client Due Diligence & Evidence Storage (`client-due-diligence`, `ADR 0039`, `0025_registers_cdd_and_org_type_keys_expand`):** Client CDD lives as client-subject `CORE_REGISTER_TYPES.cdd` records (`person_id` XOR `organisation_id`, statuses `in_progress`, `recorded`, `archived`, `superseded`, with `systemOnly` transitions `record_cdd` and `upgrade_to_high_risk` enforced in `validateRegisterTransitionExecution` via `viaDedicatedWorkflow` while still requiring `cdd:record` in `actorPermissionSet`, refusing extra firm-defined `additionalFields` in schema/Zod/engine, and blocked from generic create/update/non-archive register routes with identical `NOT_FOUND` parity `R770`/`R800` when `!cdd:view` or hidden employee-client) using SQL visibility `REGISTER_RECORD_VISIBLE_SQL_PREDICATE` (converged with `buildMatterHiddenFromViewerSql`, `R755`, plus full employee-client CDD hiding via `canViewEmployeeSubjectCdd` when `!canViewRisk && !canAccessRestrictedMatters` and the actor has no active matter participation for that employee including `relationshipPartnerId`, `R747`, `R771`). Client risk tier (`R799`) is derived firm-wide (`includeRestrictedMatters: true`) across card, creation, completion, and gate without revealing causing matters, and `buildClientCddSummaryInternal` filters each checklist item's `evidenceRefs` into slim `CddChecklistItemEvidenceSummary` entries (`artifactId`, `displayName`, `downloadable`, optional `downloadUrl`, zero cross-subject filenames or `blobKey`s, `R801`). Configuration under `cdd.*` (`cdd.enabled`, `cdd.clientTypeMapping` mapping `organisation_type` choice `systemKey`s to `individual`, `company_or_llp`, `trust_charity_or_partnership`, `cdd.riskTierMapping` mapping `risk_rating` `systemKey`s to `standard`/`high`, `cdd.checklists.{standard,highAdditional}`, `cdd.recheckIntervalsMonths.{standard: 36, high: 12}`, `cdd.reminderScheduleDaysBefore`, and `cdd.maxEvidenceFileSizeBytes`) drives checklists, `aml_and_cdd_queue` (`HomeClient`), and `register-reminders` alerts. Uploaded evidence flows through `POST /api/evidence/upload` (checking `Content-Length` before parsing, enforcing `ALLOWED_EVIDENCE_MIMES` for PDF, JPEG, PNG, HEIC/HEIF, Word, Excel, and PowerPoint plus `verifyEvidenceMagicBytes` signature verification and `scanBytesForMalwareAndMacros` pre-storage scan before `putObject` and transactional `TenantEvidenceArtifactRepository.createArtifactInTx` with same-TX `recordId = createdArtifact.id` upload audit) and `GET /api/evidence/download` (validating `'cdd:view'`, HMAC `ScopedDownloadToken`, tenant/subject ownership returning `NOT_FOUND` for missing or hidden employee-client subjects, and RFC 5987 safe MIME disposition). Both `public.intake_check_records.subject_id` and `public.evidence_artifacts.subject_id` repoint inside `executeMergeInTransaction` (`R754`), and neither CDD records nor `'evidence'` blobs are purged by enquiry anonymisation or usage retention jobs (five-year post-relationship disposal tracked under `B27`, `R758`). Permissions: `cdd:view`, `cdd:record`, and `saveCddConfigAction` (`admin:access` with `mfaVerified === true`); `admin` and `finance` hold neither `cdd:view` nor `cdd:record`, and neither `intake` nor `enquiries_coordinator` holds `cdd:view` (`R748`, `R767`). **Migration `0025` Rollback & Recovery (`R788` Option B):** Rolling back `0025_registers_cdd_and_org_type_keys_expand` drops `public.evidence_artifacts` and `public.tenant_evidence_artifact_id_seq` while leaving uploaded blobs in `tenant-<tenantId>-<env>/evidence/...`; before running `downSql` in any non-empty environment, export `public.evidence_artifacts` and `cdd` rows in `register_records` to backup storage and enable maintenance mode; to recover after an accidental rollback, re-apply `0025` `upSql`, restore `public.evidence_artifacts` (resetting `tenant_evidence_artifact_id_seq` above max EVD number), and reconcile unreferenced blobs using `register_records.field_values_json` (`checklistItems[].evidenceRefs` / `supportingEvidence`) and `audit_entries` (`record_type = 'evidence_artifact'`).
- **High-Risk Opening Sign-Off, Work-Type Opening Gate & Configurable Matter Numbering (`matter-opening-and-risk`, `sign-off-queue`, `registers-engine`, `tenant-settings`, `authentication-rbac-and-mfa`, `ADR 0039`, `ADR 0040`, `0026_opening_gate_overrides_and_numbering_expand`):** Migration `0026` adds `public.matter_opening_gate_overrides` (`tenant_opening_override_id_seq`), `public.matters.number_sequence_key`, and `public.matters.number_sequence_value` with a non-destructive sequence backfill while deferring a non-draft unique index on `matter_number` until tenant duplicate audits complete (`B29`, `R743`, `R744`). `CORE_REGISTER_TYPES.high_risk_opening` (`HRO-`, `systemCreatedOnly: true` identified by server-owned `createdById === 'system:matter_opening'` [`R791`] and refusing manual `createRegisterRecordService`, generic `updateRegisterRecordDetailsService` edits, `fieldUpdates` on transitions, unknown keys in `validateRegisterFieldValues`, and `typeOverrides.high_risk_opening.enabled: false` in both schema and Zod) enforces `allowAdminBypass: false`, sequential independent **Partner** (`partner_approve`, forbidding the matter's `leadFeeEarnerId` and `responsiblePartnerId`, `R764`) → **different Risk & Compliance officer** (`compliance_approve`, checking `mustDifferFromPreviousApprover` scoped strictly to the current active approval cycle using transition `resetsApprovalCycle` per ADR 0039 §4, `R781`, `Suggestion 4`, plus forbidding `leadFeeEarnerId` / `responsiblePartnerId`, `R793`), and `withdraw_opening` (`systemOnly: true`, passing caller permissions with `viaDedicatedWorkflow: true`, `Suggestion 7`) triggered automatically on down-score below High or prospective abandonment. Note `risk_rating.sensitive` elevates client CDD tier in S1-04 and does **not** trigger `high_risk_opening` — only **High** or **Critical** matters trigger `high_risk_opening`. unapproved restricted matches, allowing active `conflict_cleared` override only when `gateConfig.allowConflictOverride` is `true` [`R794`] and never for 'Referred'/'Declined'), refuses `DRAFT`/unsubmitted matters with `'Save and submit this matter before opening it.'` (`R761`), checks **every** client (`clientId` + `additionalClientIds`) for unexpired CDD sufficient for their derived tier (`high` required when high-risk, checking `isClientCddSubjectVisibleToViewer` including when an employee-client has no CDD record [`R792`], keeping gate decisions unmasked while emitting `rawSatisfied: null`, `canOverride: false`, `statusSummary: 'Not available to you'`, neutral blocking text, and masked UI pill [`R796`]), and requires `systemCreatedOnly` linked HRO approval (`R764`), re-reading locked `FOR UPDATE` rows (`MATTER_CONCURRENCY_CONFLICT` if `rowVersion` changed across `updateMatterConflictRecord`, `signOffMatterCostsRecord`, and `openProspectiveMatterRecord`, `R762`, `R795`) and locking `public.matters` before `public.register_records` across save/conflict/sign-off/override/compliance paths (`Suggestion 15`), while exempting server-only PMS imports (`createRecordFromPms`) with explicit audit metadata and shipping only a slim `OpeningGateHighRiskRecordView` (`id`, `reference`, `status`, nullable stage approver names [`R797`], `rowVersion`) to Only `partner` and `managing_partner` hold `matter:opening_gate:override` (`overrideMatterOpeningPreconditionRecord` / `revokeMatterOpeningOverrideRecord`, enforcing >=10-char override and revoke reasons and refusing post-opening or aborted-matter revocations [`Suggestion 5`]; excluded from `admin`, `risk_compliance`, `supervisor`, and `fee_earner`), refusing overrides where `allowCddOverride` or `allowConflictOverride` is `false` or CDD is masked. Token-based `matterNumbering` (`core/src/domain/matterNumbering/index.ts`, `{CLIENT_REF}`, `{SEQ}`/`{SEQ:1..8}`, `{YYYY}`, `{YY}`, `{DEPT}`, `sequenceScope`: `'client_ref_prefix' | 'firm' | 'year' | 'department'`, `emptyTokenFallback`, schema `superRefine`, save-time and allocation-time `validateMatterNumberingConfig` [`R769`, `Suggestion 2`] pairing `year`/`department`/`client_ref_prefix` scopes with required pattern tokens plus `{SEQ}`, `allocateNextMatterNumber`, `B6` monotonic allocation, ignoring caller-supplied `matterNumber` on creation/update and editable config persisted via MFA-guarded `saveMatterNumberingConfigAction` / `saveMatterNumberingConfigRecord`) replaces fixed `client_ref_prefix` assembly with exact `{CLIENT_REF}-{SEQ:4}` / `cleanLegacyClientRefPrefix` default parity (`R745`; interactive Admin preview widget and `{WORK_TYPE}`/`{ENTITY}` tokens deferred to `B30`/`B31`). **Connection-pool headroom (`Suggestion 13`, `Suggestion 8`):** `allocateNextMatterNumber`, CDD access checks (`listVisibleMattersForEntity`), and client CDD tier derivation (`deriveClientCddRiskTierForSubject`) run on separate pooled PostgreSQL connections while the caller holds the `public.matters` `FOR UPDATE` row lock; production deployments must size PostgreSQL pools with sufficient headroom (`maxPoolSize >= 2 * peakConcurrentMatterSubmissions`) to avoid pool-exhaustion self-deadlock. `R757` aligns Home `sign_off` `write_off` approvals to accept `signoff:approve` OR `register:approve` (`Partner`, `Managing Partner`, `Risk & Compliance`, `Supervisor`).
